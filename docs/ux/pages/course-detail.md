# Course detail UX direction

- **Observed:** Course pages answer fit, prerequisite, outcome, format, time
  commitment, project, and availability questions before the primary action.
- **Previously decided:** Learning routes may use scoped Software Signal
  Learning identity and components; critical deadlines and next actions stay
  visible rather than hidden in disclosures.
- **Observed:** A launched course can expose a concrete application or
  notification action. A pipeline course communicates its current status and
  expected next step without pretending enrolment is available.
- **Derived principle:** The page is a considered enrolment decision aid, not a
  high-pressure sales page.

## Invariants

1. Prerequisites and intended learner are explicit.
2. Outcomes describe observable capability, not vague transformation.
3. Delivery format, effort, project, and status are findable before action.
4. One dominant current action is used in the status/action region.
5. Pipeline and launched states remain truthful and visibly distinct.
6. Narrow layouts preserve the decision order and keep long details readable.
