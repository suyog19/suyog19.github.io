# System detail UX direction

- **Observed:** System details reuse the article reading architecture while
  structuring the narrative around problem, approach, implementation, and
  learning.
- **Observed:** Demos and diagrams are supporting evidence. They remain linked to
  explanatory context rather than presented as unexplained spectacle.
- **Derived principle:** A system page should make tradeoffs and limits visible;
  it is an engineering account, not a product launch page.

## Invariants

1. The practical problem and system boundary are clear.
2. Architecture or interaction evidence is explained in accessible prose.
3. Status and limitations are honest.
4. Demo actions are clearly distinguished from ordinary reading links.
5. Shared article-detail readability and responsive behavior are preserved.
