# Systems page UX direction

- **Observed:** Systems presents working software explorations and experiments,
  positioned as practical evidence rather than a polished product catalogue.
- **Observed:** Entries explain problem, approach, and what changed, with status
  and context where relevant.
- **Derived principle:** Lead with the engineering question and learning value;
  technology names support that story rather than becoming the headline.
- **Derived principle:** Distinguish a working demo, experiment, and architecture
  exploration honestly so visual polish does not overstate maturity.

## Invariants

1. Every system has a clear practical purpose or question.
2. Status and scope are candid.
3. Comparable entries use consistent metadata and navigation.
4. Detail is available without making the index unreadably dense.
5. Cards remain content-led, flat, and consistent with the public site.
